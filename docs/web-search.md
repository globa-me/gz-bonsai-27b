# Веб-поиск

## Выбранная схема

В `0.5.0` веб-поиск выключен по умолчанию и использует два официальных API:

- **Tavily Keyless** — работает сразу, без аккаунта и пользовательского ключа;
- **Brave Search API** — включается автоматически после проверки личного ключа и подходит для более активного использования.

Если Brave key сохранён, ошибка Brave не вызывает скрытого перехода к другому провайдеру: запрос останавливается с понятной ошибкой. После удаления ключа снова используется Tavily Keyless.

## Почему не Bing RSS, Jina или публичный SearXNG

Неофициальный Bing RSS не гарантировал релевантную выдачу и был причиной неправильных источников в `0.4.0`. Живая проверка 22 сентября 2026 года показала, что `s.jina.ai` без ключа отвечает HTTP 401. Публичные SearXNG-инстансы различаются по движкам, лимитам и поддержке JSON; официальный проект рекомендует собственный инстанс, поэтому случайный публичный сервер не подходит как релизная зависимость.

Tavily документирует keyless-запрос через `X-Tavily-Access-Mode: keyless`; живой русский запрос вернул HTTPS-источники, включая `primeminister.kz` и `gov.kz`, за 1,26 секунды. Но сам провайдер называет режим бесплатным, rate-limited и предназначенным для exploration/light use. Поэтому UI явно показывает активного провайдера и предлагает Brave как опциональный путь с большими лимитами.

Официальные материалы:

- Tavily Keyless: <https://docs.tavily.com/documentation/keyless>;
- Tavily Privacy Policy: <https://www.tavily.com/privacy>;
- Brave Search API: <https://api-dashboard.search.brave.com/app/documentation>;
- SearXNG Search API: <https://docs.searxng.org/dev/search_api>.

## Безопасность и приватность

- поиск выполняется только после включения кнопкой с глобусом;
- провайдер получает текст только текущего запроса, но не историю чата и не RAG-документы;
- включён `safe_search`; принимаются только HTTPS URL без credentials, нестандартного порта, loopback/private IP и известных adult-host tokens;
- сетевой ответ ограничен 2 МБ, запрос — 400 символами и 50 словами, число источников — пятью;
- источник и snippet передаются модели как недоверенные данные с запретом исполнять инструкции из результатов;
- при timeout, лимите, ошибке авторизации или пустой безопасной выдаче ответ модели не запускается;
- отдельные карточки найденных URL, заголовков и snippets доступны только до закрытия приложения и удаляются из IndexedDB при сохранении/загрузке; ссылки, которые модель включила в текст ответа, остаются частью этого ответа;
- Brave key проверяется живым запросом и хранится в macOS Keychain; он не записывается в конфиг, историю или диагностику;
- диагностика сохраняет только провайдера, длительность, число принятых результатов и код ошибки — без query и key.

Tavily сообщает, что keyless-трафик имеет меньшие договорные гарантии, а query data может использоваться для улучшения сервиса и в отдельных случаях передаваться поисковым индексам. Поэтому приложение показывает это до настройки Brave и рекомендует не вводить конфиденциальные данные в веб-поиск.

## Следующий этап

Для гарантированного no-key UX без общего публичного лимита нужен собственный проектный gateway с серверным Brave credential, бюджетом, rate limiting и опубликованной privacy policy. Встраивать общий секрет в `.app` нельзя: его можно извлечь из дистрибутива.
