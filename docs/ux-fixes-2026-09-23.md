# Исправления UX/UI в 0.6.0, 23 сентября 2026 года

Это описание реализации релиза `0.6.0`. Проверка подписанного DMG записана в [e2e-0.6.0.md](e2e-0.6.0.md). Исходный список проблем: [ux-audit-2026-09-23.md](ux-audit-2026-09-23.md). Метаданные моделей и закреплённые артефакты не менялись; перед работой просмотрены официальные страницы моделей PrismML на Hugging Face и документация форка PrismML `llama.cpp`.

## Принятые решения

1. **Ошибки RAG.** Ошибка чтения индекса или пустой результат останавливают отправку запроса; черновик остаётся в поле ввода. Ошибка показывается у чата, поэтому переключение во время импорта не выводит её в другом чате.
2. **Один файл — один источник.** Новые JSON-индексы сохраняют нормализованный полный текст наряду с перекрывающимися частями. Версия 1 читается без миграции и восстанавливается по совпадающим границам частей. Если все выбранные документы помещаются в лимит 9000 символов и оценка `/tokenize` не превышает 60% выбранного контекста, в запрос попадают полные тексты. В остальных случаях остаётся BM25. Цитаты сгруппированы по файлу, выдержки раскрываются под ответом. Это сохраняет экономное поведение для длинных файлов и предотвращает выдачу четырёх частей одного PDF как четырёх «документов».
3. **Ответы.** Отдельная команда `cancel_chat` прерывает HTTP streaming одного запроса, включая гонку на регистрации. В UI есть «Остановить» и повтор для последнего неудачного или остановленного ответа. Полученный до обрыва текст остаётся в истории; ошибка выводится отдельно. Повтор использует исходное сообщение и его вложения.
4. **Размер истории.** В API передаются последние восемь сообщений, но старые файлы и base64 изображений не прикладываются заново. Содержимое вложений остаётся локально в истории. Под полем ввода об этом есть пояснение.
5. **Переключение чатов во время импорта.** Загрузка документов и сообщения об ошибках привязаны к ID исходного чата. Глобальная блокировка предотвращает параллельный импорт; индикатор показывается только в исходном чате.
6. **Первый запуск.** Быстрый старт показывает самый лёгкий вариант, прошедший эвристический RAM-порог, затем действия установки, запуска и открытия чата. Другие варианты свернуты. Выбранный вручную GGUF показывается отдельно с собственным действием запуска. Совместимость RAM остаётся оценкой, а не измерением.
7. **Файлы.** При перетаскивании PDF/DOCX подключаются к чату, изображения и код относятся к сообщению; для TXT/MD/CSV/JSON пользователь выбирает срок действия. Кнопки подписаны. Выбор можно отменить.
8. **Удаление.** «Убрать из чата» снимает привязку. «Удалить с устройства» после подтверждения удаляет JSON-индекс, если он не используется другим чатом. Сохранённые ранее ответы и цитаты не изменяются.
9. **Читаемость.** Укрупнены операционные подписи и кнопки, добавлены видимые названия действий, `role=status`/`role=alert` для фоновых процессов и ошибок. Источники ответа открываются с клавиатуры через стандартный `details`.
10. **История.** Сохранение в IndexedDB поставлено в последовательную очередь с задержкой 350 мс, принудительным сбросом при скрытии или закрытии окна и видимым состоянием «сохранено / ошибка / повторить». Если чтение истории не удалось, запись блокируется до успешного повторного чтения, чтобы не затереть прежние чаты пустым состоянием.
11. **Метки источников.** Нативная проверка показала, что пример `[D1], [D2]` в инструкции провоцировал 1.7B-модель цитировать несуществующий `[D2]` при одном документе. Теперь инструкция перечисляет только метки реально переданных файлов и просит не придумывать другие.
12. **Закрытие приложения.** При обычном `Cmd+Q` тестовая сборка оставила `llama-server` на порту 8080. Добавлена остановка sidecar при событии выхода Tauri; повторный запуск и освобождение порта проверены нативно.
13. **Бюджет полного PDF.** Повторная нативная проверка обнаружила смешение символов и токенов: документ на 8323 символа и 2091 токен ошибочно отправлялся в BM25, потому что его длину в символах сравнивали с размером контекста 8192 токена. Ограничение полного текста теперь равно 9000 символам независимо от размера контекста, а фактическое помещение проверяет локальный `/tokenize`.
14. **Вопросы о начале и конце длинного файла.** Когда полный текст не помещается, поиск для одного файла теперь сохраняет первый и последний фрагменты при соответствующем вопросе. Для запроса о документе целиком выбираются начало, конец и распределённые по середине выдержки. Обычные точечные вопросы по-прежнему используют BM25.
15. **Повторяющийся ответ.** Во время нативного теста маленькая модель зациклилась на одной фразе. Поток останавливается после пяти подряд повторов длинного фрагмента и показывает локализованную причину; уже полученный текст остаётся в чате. Повторная нативная проверка выявила ложное срабатывание, когда пользователь явно попросил повторить строку 12 раз. Для ограниченного запроса порог теперь равен указанному числу повторов плюс один; бесконечное повторение и обычные ответы сохраняют исходный порог.
16. **Сохранение при аварийном завершении.** Нативный `kill -9` во время длинного ответа воспроизвёл потерю нового запроса: прежний debounce не успевал записать историю, пока приходили токены. Теперь запрос и пустой ответ записываются в IndexedDB до обращения к модели, а активная генерация сохраняется не реже чем раз в 1,5 секунды. Если контрольная запись не удалась, генерация не запускается: интерфейс сохраняет запрос для повтора, а при повторной попытке оставляет прежний ответ. Ответ с флагом `pending` после перезапуска получает понятную ошибку и кнопку повтора.
17. **Sidecar после `kill -9`.** Сторожевой процесс macOS ждёт закрытия pipe от приложения и останавливает `llama-server`, даже когда Tauri не получает событие выхода. При штатной остановке модели сторожевой процесс снимается.
18. **Пустой чат с выбранной моделью.** После остановки сервера чат раньше предлагал «настроить модель», хотя GGUF и runtime уже выбраны. Теперь он предлагает запустить модель прямо из чата; во время запуска и остановки показывает соответствующий статус и не предлагает повторный запуск.

## Проверено

- `npm test`: 27/27, включая объединение цитат, границы истории, маршрутизацию файлов, порядок сохранения, восстановление незавершённого ответа и распознавание ограниченного запроса на повторы.
- `npm run build`: TypeScript и Vite успешно.
- `cargo test --locked`: 21/21, включая полный документ из четырёх частей, чтение старого индекса без повторения overlap, выбор концов длинного файла и обнаружение цикла ответа.
- `cargo fmt --check` и `cargo clippy --locked --all-targets -- -D warnings`: успешно.
- Закреплённый локальный `llama-server` с установленной Bonsai 1.7B запущен на отдельном loopback-порту: health и `/tokenize` работают. Для существующего четырёхчастного PDF локально проверено восстановление текста: 4829 символов, 1902 токена. Содержимое PDF не выводилось и не отправлялось во внешнюю сеть.
- Vite preview просмотрен в RU/EN: быстрый старт и каталог отображаются без видимого переполнения.
- Нативная unsigned debug-сборка с отдельным bundle identifier `com.bonsai.desktop.audit20260923` проверена на Apple M3 Pro без обращения к данным установленной версии для записи. Через системный диалог подключён синтетический TXT длиной 7310 символов: Rust создал семь внутренних частей, а чат показал один документ и один источник `[D1]` с пометкой «Весь документ». Модель вернула маркеры `CEDAR-17` из начала и `MAPLE-91` из конца файла.
- В нативном чате проверены остановка длинной генерации с сохранением частичного ответа, повтор без дублирования сообщения пользователя, восстановление истории и источников после перезапуска, отказ от удаления документа, подключённого к другому чату, затем отключение и удаление индекса. После исправления инструкции новый ответ на один документ использовал только `[D1]`.
- Индекс синтетического файла удалён между подключением и отправкой запроса: приложение не отправило запрос модели, показало ошибку чтения и сохранило черновик. Повторный импорт создал индекс заново, после чего тот же запрос успешно вернул оба маркера. После `Cmd+Q` порт 8080 свободен.
- В обновлённой нативной debug-сборке импортирован синтетический четырёхстраничный PDF: извлечено 4333 символа, индекс содержит четыре внутренние части. Англоязычный запрос получил полный документ и вернул начальный маркер `PINE-204`, конечный `BIRCH-908` и один источник `[D1]`. Переключение интерфейса RU → EN также проверено.
- Отдельный синтетический PDF на 8323 символа и семь частей показал ошибочный переход на выдержки в предыдущем коде. После исправления тот же PDF отображался как «Весь документ». Его 80 однообразных строк вызвали некачественный многословный ответ модели 1.7B; для этого добавлен предохранитель от точных повторов.
- Синтетический TXT длиной 24412 символов дал 21 внутреннюю часть. При вопросе о *opening and closing markers* сокращённые крайние выдержки (1 и 21) позволили модели вернуть `TOPAZ-311` и `OPAL-722` с `[D1]`; сохранённые источники показывают выбранные номера частей. До сокращения тот же вопрос давал ошибочный ответ о недостатке данных.
- До исправления аварийного сценария `kill -9` тестовой оболочки во время длинного ответа оставил сервер на порту 8080 и потерял только что отправленный запрос. После исправления повторный `kill -9` сразу освободил порт и завершил сторожевой процесс. После повторного открытия нативный интерфейс показал запрос `CRASH-CHECK-924`, частичный ответ примерно до пункта 180 и локализованную ошибку восстановления. После запуска модели появилась кнопка повтора; повтор начал генерацию без дублирования пользовательского сообщения, его остановка сохранила новый частичный ответ.
- Штатная кнопка остановки модели в изолированной сборке освободила порт 8080 и завершила сервер со сторожевым процессом. Переключение EN → RU вернуло русские строки интерфейса. Во время импорта синтетического TXT объёмом 3 МБ открыт другой чат; после завершения индекс `bonsai-audit-import-switch.txt` оказался только в исходном чате, а индикатор импорта не появился в другом.
- После этой проверки обнаружена и исправлена ветка ошибки IndexedDB при контрольной записи: раньше она всё равно запускала модель. Новая ветка компилируется и проходит тесты, но искусственно вызванный сбой записи в нативном UI ещё не воспроизведён.
- На экране пересобранного приложения визуально обнаружена неверная подсказка «Сначала настройте локальную модель» при уже выбранной, но остановленной модели. После исправления в нативном UI появилась подсказка «Запустите локальную модель»; запуск прямо из чата показал промежуточный статус, затем «Чем помочь сегодня?». Остановка через меню статуса вернула правильное состояние.
- Источник `[D1]` в нативном чате раскрывается клавишей пробела и остаётся в фокусе. Запрос на 12 дословных повторов сначала ошибочно завершился после пяти повторов с сообщением о цикле. После поправки и пересборки тот же запрос завершился штатно: ответ содержит 11 повторов, метрики 220 выходных токенов, сообщения о цикле нет. Точное число повторов зависит от модели; интерфейс больше не обрывает разрешённые повторы до заданного предела.
- В Web Inspector изолированной нативной сборки временно подменён `IDBFactory.prototype.open` на ошибку; обычное присваивание `indexedDB.open` на WebKit оказалось неэффективным и не считалось проверкой. Запрос `AUDIT-IDB-FAIL-926` при настоящем отказе показал «Не удалось сохранить историю» и кнопку повтора без ответа модели. После восстановления штатного метода повтор вернул «нет» с метриками, статус истории стал «История сохранена». Данные установленного приложения не затрагивались.

Для повторения нативной проверки без записи в данные установленного приложения:

```bash
npm run tauri -- build --debug --bundles app --no-sign --config '{"identifier":"com.bonsai.desktop.audit20260923","productName":"GZ Bonsai Audit"}'
open -a 'src-tauri/target/debug/bundle/macos/GZ Bonsai Audit.app'
```

В изолированной сборке модель 1.7B выбиралась через «Ручная настройка» из уже установленного локального GGUF. Индексы и чаты этой сборки находятся в отдельном `Application Support/com.bonsai.desktop.audit20260923`.

## Границы проверки и следующий шаг

- В изолированной debug-сборке не проверены нативные сценарии VoiceOver и остановка действительно бесконечного повтора после последней поправки (порог проверен unit-тестом; модель на открытый запрос ответила одной строкой). Подписанная сборка проверена отдельно в [e2e-0.6.0.md](e2e-0.6.0.md). Проверка `kill -9` не доказывает восстановление при сбое ОС или отключении питания.
- `/tokenize` оценивает текст, но не весь шаблон чата и мультимодальные вложения; близкие к пределу контекста запросы могут получить ошибку сервера. Нужен подсчёт всего собранного `messages` на закреплённом runtime.
- Восстановление текста старого индекса убирает дубли на совпадающих границах, но не может гарантировать точное исходное форматирование; повторный импорт создаёт индекс с полным нормализованным текстом.
- При аварийном завершении до commit транзакции IndexedDB самые последние токены всё ещё могут не сохраниться. Контрольная запись гарантирует сохранение запроса только после её успешного завершения; если IndexedDB выдаёт ошибку, интерфейс показывает ошибку сохранения и позволяет повторить попытку.
